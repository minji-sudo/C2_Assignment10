과제 10: 정렬 알고리즘의 성능 및 안정성 비교

1. 실행방법
난수 시드를 12345로 고정해서 누가 돌려도 같은 결과가 나온다. (시드를 바꾸면 무작위/부분 정렬 쪽 숫자가 조금씩 달라진다)

   
2. 구현 기준 
데이터	key1, key2, order(원래 입력 순서) 구조체. 정렬 기준은 key1만 사용, order는 안정성 검증용
비교 횟수	두 데이터의 key1을 비교할 때마다 1회. 반복문 조건(i < n 등)은 제외
이동 횟수	Data 구조체 통째로 복사/대입할 때마다 1회. swap은 temp를 쓰므로 3회
선택 정렬	최솟값 위치가 현재 위치와 같으면(min == i) 교환 생략
삽입 정렬	cur = a[i] 1회 + 한 칸씩 미는 대입 + 최종 위치 대입 1회를 전부 센다
제외	원본 배열 복사, 데이터 생성, qsort로 하는 사전 정렬, 부분 정렬용 교란은 횟수에 포함하지 않음

세 알고리즘(+버블 조기 종료)은 매 회차마다 같은 원본 배열의 복사본을 받는다. 일반 버블과 조기 종료 버블은 bubble_core() 하나를 같이 쓰고 early 플래그만 다르게 해서, 조기 종료 여부 말고는 코드가 완전히 같게 했다.


3. 안정성 검증
검증 방법

각 데이터에 원래 입력 순서를 저장하는 order 필드를 넣었다. 정렬 후 인접한 두 원소가 key1이 같은데 order가 뒤집혀 있으면 "순서가 바뀐 쌍"으로 세었다. 이 개수가 0이면 안정 정렬이다.

두 가지로 검증했다.

과제에 나온 작은 예시 4개 — (527,100) (527,200) (125,300) (892,400)을 정렬하고 눈으로 확인
중복이 많은 큰 데이터 — 10,000개, key1을 0~99로 제한해서 같은 키가 엄청 많이 나오게 만들고 위반 쌍 개수를 계산 (key1 범위를 100만으로 두면 중복이 거의 안 생겨서 검증이 약해짐)
결과

작은 예시 (정렬 후):

알고리즘	결과	527끼리의 순서
선택 정렬	(125,300) (527,200) (527,100) (892,400)
버블 정렬	(125,300) (527,100) (527,200) (892,400)	
삽입 정렬 (>)	(125,300) (527,100) (527,200) (892,400)	
삽입 정렬 (>=)	(125,300) (527,200) (527,100) (892,400)	

큰 데이터 (10,000개, 중복 많음):

알고리즘	결과	순서 뒤집힌 쌍
선택 정렬	Not Stable	3,358
버블 정렬	Stable	0
삽입 정렬 (>)	Stable	0
삽입 정렬 (>=)	Not Stable	9,900

(모든 경우 정렬 자체는 올바르게 되었다)




삽입 정렬	비교·이동 모두 입력 상태에 가장 민감하다. 정렬에 가까울수록 O(n)에 가깝고, 역순이면 O(n²). 이번 실험에서 무작위·부분 정렬 모두 가장 좋았다. 안정성도 >를 쓰면 확보된다.

입력 상태 순서(좋은 순): 정렬됨 < 부분 정렬 < 무작위 < 역순. 이 순서는 삽입 정렬에서 가장 뚜렷하게 나타나고, 선택 정렬은 비교 기준으로는 입력 상태가 영향이 없었다.
