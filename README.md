과제 10: 정렬 알고리즘의 성능 및 안정성 비교

1. 실행방법
난수 시드를 12345로 고정해서 누가 돌려도 같은 결과가 나온다. (시드를 바꾸면 무작위/부분 정렬 쪽 숫자가 조금씩 달라진다)

   
3. 구현 기준 
데이터	key1, key2, order(원래 입력 순서) 구조체. 정렬 기준은 key1만 사용, order는 안정성 검증용
비교 횟수	두 데이터의 key1을 비교할 때마다 1회. 반복문 조건(i < n 등)은 제외
이동 횟수	Data 구조체 통째로 복사/대입할 때마다 1회. swap은 temp를 쓰므로 3회
선택 정렬	최솟값 위치가 현재 위치와 같으면(min == i) 교환 생략
삽입 정렬	cur = a[i] 1회 + 한 칸씩 미는 대입 + 최종 위치 대입 1회를 전부 센다
제외	원본 배열 복사, 데이터 생성, qsort로 하는 사전 정렬, 부분 정렬용 교란은 횟수에 포함하지 않음

세 알고리즘(+버블 조기 종료)은 매 회차마다 같은 원본 배열의 복사본을 받는다. 일반 버블과 조기 종료 버블은 bubble_core() 하나를 같이 쓰고 early 플래그만 다르게 해서, 조기 종료 여부 말고는 코드가 완전히 같게 했다.


4. 안정성 검증
검증 방법

각 데이터에 원래 입력 순서를 저장하는 order 필드를 넣었다. 정렬 후 인접한 두 원소가 key1이 같은데 order가 뒤집혀 있으면 "순서가 바뀐 쌍"으로 세었다. 이 개수가 0이면 안정 정렬이다.

두 가지로 검증했다.

과제에 나온 작은 예시 4개 — (527,100) (527,200) (125,300) (892,400)을 정렬하고 눈으로 확인
중복이 많은 큰 데이터 — 10,000개, key1을 0~99로 제한해서 같은 키가 엄청 많이 나오게 만들고 위반 쌍 개수를 계산 (key1 범위를 100만으로 두면 중복이 거의 안 생겨서 검증이 약해짐)
결과

작은 예시 (정렬 후):

알고리즘	결과	527끼리의 순서
선택 정렬	(125,300) (527,200) (527,100) (892,400)	뒤집힘 ❌
버블 정렬	(125,300) (527,100) (527,200) (892,400)	유지 ✅
삽입 정렬 (>)	(125,300) (527,100) (527,200) (892,400)	유지 ✅
삽입 정렬 (>=)	(125,300) (527,200) (527,100) (892,400)	뒤집힘 ❌

큰 데이터 (10,000개, 중복 많음):

알고리즘	결과	순서 뒤집힌 쌍
선택 정렬	Not Stable	3,358
버블 정렬	Stable	0
삽입 정렬 (>)	Stable	0

(모든 경우 정렬 자체는 올바르게 되었다: sorted=OK)



이미 정렬된 데이터

선택 정렬: 비교는 그대로 49,995,000인데 이동은 0이다. 최솟값이 항상 제자리라 교환을 안 하기 때문이다. 비교 횟수는 입력에 전혀 영향을 안 받는 알고리즘이라는 게 확실히 보인다.
일반 버블: 교환이 없어도 정해진 모든 pass를 돌아서 비교 49,995,000회.
조기 종료 버블: 첫 pass 한 번(9,999회 비교)만 돌고 끝난다. 5,000배 이상 줄어든다. 조기 종료가 진짜 효과를 보는 유일한 상황이다.
삽입: 각 원소가 바로 앞 원소와 한 번만 비교하고 멈추므로 비교 n-1 = 9,999회. 이동은 cur 저장 + 최종 대입으로 원소당 2회 → 19,998회. (이동이 0이 아닌 건 제자리여도 대입을 센다는 내 카운트 규칙 때문)

역순 데이터 (최악)

비교는 선택·버블·삽입이 전부 49,995,000으로 같다. 삽입 정렬도 모든 원소를 맨 앞까지 밀어야 해서 평소의 2배로 늘어난다.
이동은 버블이 약 1억 5천만으로 가장 심하다. 역전쌍이 n(n-1)/2 ≈ 5,000만 개이고 교환 1번에 이동 3회이기 때문이다. 삽입은 약 5,000만, 선택은 약 1.5만으로 선택 정렬이 이동 면에서 제일 좋다. (앞뒤를 맞바꾸는 교환 약 5,000번 × 3)
조기 종료 버블은 마지막 pass까지 매번 교환이 일어나므로 효과가 전혀 없다. (일반 버블과 숫자가 완전히 똑같다)

일부 정렬된 데이터

삽입 정렬이 비교 약 305만 / 이동 약 306만으로 압도적이다. 무작위(약 2,500만)의 1/8 수준이다. 삽입 정렬의 비용은 대략 n + 역전쌍 개수라서, 정렬에 가까울수록 빨라진다.
버블 이동 9,117,621 ÷ 3 = 3,039,207이 역전쌍 개수이고, 삽입 이동 3,059,205 − 19,998 = 3,039,207과 정확히 일치한다. 두 알고리즘의 이동이 모두 "역전쌍 개수"에 비례한다는 이론을 숫자로 확인했다.
조기 종료 버블은 비교가 49,701,239로 약 29만(0.59%) 줄었는데 기대보다 효과가 작다. 정렬된 배열에서 멀리 있는 작은 값은 pass 한 번에 한 칸씩만 앞으로 이동하기 때문에, 90%가 정렬되어 있어도 몇 개의 흐트러진 원소가 끝까지 pass를 요구한다. 그래서 거의 모든 pass를 돌게 된다. (500번 교환으로 생긴 작은 값 하나가 5,000칸 뒤에서 오면 5,000번 pass가 필요함)
선택 정렬은 이동이 1,503으로 매우 적지만 비교는 여전히 49,995,000이다.
종합
알고리즘	특징
선택 정렬	비교는 항상 n(n-1)/2로 고정. 대신 이동이 가장 적다. (최대 약 3n). 이동 비용이 큰 데이터라면 장점이 있지만 불안정하다.
버블 정렬	비교는 고정, 이동은 역전쌍 × 3이라 제일 많다. 조기 종료는 거의 정렬된 데이터에서만 효과가 있다.
삽입 정렬	비교·이동 모두 입력 상태에 가장 민감하다. 정렬에 가까울수록 O(n)에 가깝고, 역순이면 O(n²). 이번 실험에서 무작위·부분 정렬 모두 가장 좋았다. 안정성도 >를 쓰면 확보된다.

입력 상태 순서(좋은 순): 정렬됨 < 부분 정렬 < 무작위 < 역순. 이 순서는 삽입 정렬에서 가장 뚜렷하게 나타나고, 선택 정렬은 비교 기준으로는 입력 상태가 영향이 없었다.
